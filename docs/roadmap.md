# bms-node 路线图

> 时间窗口：can-node 之后追加 1–2 周。前提是 can-node 的 CAN 骨架已经稳定，这里只加业务。

## 阶段拆分

### P0 · 复用骨架
- [ ] 从 can-node 同步 `src/can/`（**同源同步，不各改各的**）
- [ ] 与 can-node 的 DBC / 报文定义对齐

### P1 · 采样
- [ ] ADC 多通道采样
- [ ] 滤波（滑动平均 / 一阶低通，记录实测噪声）
- [ ] 采样周期与 CAN 上报周期解耦

### P2 · 保护状态机
- [ ] 四态设计：正常 → 告警 → 保护 → 恢复
- [ ] 迟滞带（防抖动，阈值不要单点）
- [ ] 每态的动作与恢复条件
- [ ] 故障码写入与查询

### P3 · UDS 对接
- [ ] `0x22` 读故障码
- [ ] `0x2E` 写阈值（注意权限与范围校验）
- [ ] `0x31` 自检例程

## 量化指标（简历要用）

- 从触发保护到切断的响应时间
- 采样噪声与滤波前后对比
- 故障注入的恢复时间

## 风险

状态机最容易做成「一坨 if」。动手前先把四个状态和迁移条件画成表，
再写代码——这张表本身就是面试时能讲的产出。

# bms-node

储能方向的 CAN 节点（STM32）。**项目 2 的第二个 profile**，复用
[can-node](https://github.com/Dik-910/can-node) 的 CAN 骨架，不重复造一套。

## 为什么单独建仓库

同一块板子、同一套 CAN 驱动，但**业务对象**完全不同：can-node 诊断的是「车」，这里诊断的是「电池」。
放在一个仓库里会互相污染简历叙事，分开更干净，也方便演示「同一骨架支撑两个 profile」的设计能力。

## 目标能力

| 模块 | 内容 |
|---|---|
| ADC 采样 | 电压 / 电流采样与滤波 |
| 阈值保护状态机 | 正常 → 告警 → 保护 → 恢复，带迟滞 |
| 故障码 | 故障记录与查询 |
| UDS 对接 | 保护状态机就是 UDS 的被诊断对象 |

## 关键耦合点

**保护状态机 = UDS 被诊断对象**，这是两个项目的技术连接点：

- `0x22` 读故障码
- `0x2E` 写保护阈值
- `0x31` 触发自检例程

## 明确不做

`SOC` / `SOH` 估算、`FOC` 电机控制、电池均衡。被问到就直说没做。

## 目录

```
src/bsp/    板级支持
src/can/    从 can-node 同步过来的 CAN 驱动（保持同源，别各改各的）
src/bms/    ADC 采样、保护状态机、故障码
test/       单测与桩测试
docs/       路线图
```
